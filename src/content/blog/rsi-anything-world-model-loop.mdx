## 一句话总结

RSI-Anything 把「Agent 自己变好」拆成三件事：**预测引导选择**（省下昂贵的外部反馈）、**反馈驱动更新**（策略与世界模型分头改进）、**配对检查把关保留**（单个组件变好不等于组装系统变好）——前两件别人做过，第三件是它真正的独门货。

> 论文：[arXiv:2610.13912 *RSI-Anything: Unlocking Recursive Self-Improvement with World Models*](https://arxiv.org/abs/2610.13912)（Gen-Verse + CUHK, 2026-10）。
> 仓库：[Gen-Verse/RSI-Anything](https://github.com/Gen-Verse/RSI-Anything)（Apache-2.0，五任务可跑）。

## 先分清：什么才算「递归」

「递归自我改进」（RSI, Recursive Self-Improvement）被用得太滥。严格的三层术语：

| 层级 | 定义 | 典型工作 |
| --- | --- | --- |
| **self-refinement** | 同一次任务内自我纠错 | 大多数 self-correction |
| **persistent self-improvement** | 改进**跨任务保留** | 记忆 / harness 进化 |
| **recursive self-improvement** | **改进机制本身被改进** | 公开证据仍为零 |

配套的三级证据阶梯，是读任何 RSI 论文的解剖刀：

1. **Task gain**：这次任务做得更好——最弱；
2. **Retained gain**：改进被保留，下次任务起点更高——RSI-Anything 的主要证据层；
3. **Improver gain**：改进的**过程**变快变准——公开系统无人做到受控证明。

RSI-Anything 的诚实之处正在这里：论文 Discussion 自陈「策略与世界模型的持续互促需要单任务联合多轮评测才能证明」，社区 issue #3 追问「某次迭代的改进是否提升了后续迭代的有效性」，一作答复指向 GUI 域的双轮更新作为最接近的演示——但**没有**提供第二轮改进率高于第一轮的受控对照。递归性落在 Retained gain 层，不多不少。

## 六步闭环，两个时间尺度

论文的形式化骨架很干净：

| 操作 | 干什么 |
| --- | --- |
| **Propose** | 策略提议候选动作 / 候选方案 |
| **Predict** | 世界模型预测每个候选的后果 |
| **Select** | 按预测效用排序选一个（信息寻求可显式启用） |
| **Evaluate** | 执行，取回**真实外部反馈** |
| **Learn** | 反馈分流：策略更新 + 世界模型适应 |
| **Retain** | 组件检查 + **配对检查**决定这对东西是否留下 |

**双时间尺度**是理解全文的钥匙：$t$ 是任务内的动作步，$k$ 是**更新-接受周期**——第 $k$ 周期被接受的系统是「策略配置 $\theta_k$ + 预测器 $\phi_k$」一对。$k$ 计的是更新次数，不是成功次数。

固定与可变的边界（论文 Table 1）：

- **整轮固定**：任务规范、评测标准、预算上限、接受与停止规则——改进不许碰考卷；
- **可变**：任务状态（动作与观测改写）、策略 $\theta$（反馈驱动提出候选版本）、世界模型 $\phi$（**有条件**才适应）；
- 关键细则：**仅扩充反馈历史不算策略或模型修订**——这正是 persistent self-improvement 与 self-refinement 的分界线。

## 三个真正的机制

### 1. 预测引导选择：同预算下省外部反馈

策略每轮提议 4 个修改候选，世界模型预测哪个最可能通过隐藏测试。核心实验（CodeContests 200 题 × 3 种子 = 600 次评测，策略固定）：

| 选择方式 | 最终通过率 | 在线测试调用 / 任务 |
| --- | ---: | ---: |
| 随机选 1 | 26.0% | 3.72 |
| 容量匹配静态验证器 | 26.3% | 3.72 |
| 固定世界模型排序 | **29.2%** | 3.71 |
| + 世界模型适应 | **31.2%** | 3.72 |

关键在**第三列**：测试调用数几乎不变（3.71 vs 3.72），即增益不是「多花钱换分数」，而是**同样少的反馈被花得更准**——预测选择 +2.83pp（95% 区间 [+0.17, +5.50]），候选排序准确率 66.5% → 72.8%。

「预测选得准」与「预测器自己变好」是两个可分离、可叠加的收益——正好对应闭环的 Select 与 Learn/Retain 两环。这也是独立评论者认可的全论文最有价值方向：**学习型预测器打败静态验证器**。

### 2. 条件性世界模型适应：策略进化后，预测会失效

这是 RSI 特有的问题：策略一旦更新，候选分布变了，旧世界模型的预测就可能过期——但也不是每轮都该重训。论文的触发条件是**三重与**：

$$
\text{Adapt} \iff \underbrace{\rho_k = \text{不可靠}}_{\text{可靠性判定}} \;\wedge\; \underbrace{n_{\text{data}} \geq \tau}_{\text{数据充足}} \;\wedge\; \underbrace{c \leq B_k}_{\text{预算充足}}
$$

三个细节值得抄作业：

- **版本隔离**：可靠性评估只允许**当前版本**的预测进误差估计，旧版本预测留作历史分析，不混入——防止好坏版本混桶；
- 覆盖不足给「证据不足」而非「可靠」——**不触发适应**，防止选择性偏差误判；
- 反馈来自**被选择的候选**，结论天然限于被覆盖范围——论文对此明确设限，是同类工作少见的严谨表述。

### 3. 配对兼容性检查：独门贡献

三道门决定保留：组件检查 $G^\pi$（新策略达标吗）、组件检查 $G^W$（新预测器达标吗）、**配对检查 $G^{pair}$**（组装后的 $(\theta_{k+1}, \phi_{k+1})$ 对比现役对）。

为什么配对检查不可省：**策略变了会改变候选分布，进而使「本来变好的预测器」在新候选上不可靠**——反之亦然。组件任一失败保留现版本，配对失败**整对回滚**。

<Callout type="note" title="一句话记住它">
「单组件变好 ≠ 组装系统变好。」世界模型排序准确率上涨与控制器成功率上涨经常背离——配对检查就是给这种背离装的闸。
</Callout>

配套还有 **E0–E3 证据分级**（确定性规则 → 学习型预测 → 专用模拟器 → 外部实测）与想象数据准入式：有效 + 效用过阈 + 不确定性够低 + 证据类别在允许集，且预测与观测字段**各自保留来源**——防止「想象污染证据」。对科学发现类应用，这是把预测安全用于学习的关键机制。

## 五领域实测

| 领域 | 设置 | RSI-Anything | 关键对照 |
| --- | --- | ---: | --- |
| 代码修复 | CodeContests 200×3 种子 | 隐藏测试 **31.2%** | 静态验证器 26.3% |
| GUI | MiniWoB++ 100 实例 | **99%** 成功，重复点击 237 → **0** | 初始 51% |
| GUI | OSWorld 桌面 | 相对初始 **+18.4%** | RLAnything +12.3% |
| 实验室规划 | LabHorizon F200 Level-2 | **46.01%** | 首版 21.80%；4B 模型压过 GPT-5.5（22.76%） |
| 反应优化 | Suzuki flow LC–MS，预算 40 次 | **96.15%** | 贝叶斯优化 82.16% |

三条最值得看的曲线：

- **实验室规划五个保留版本单调爬升**：21.80 → 38.03 → 41.99 → 44.56 → 46.01——同一个 4B 策略经五轮保留改进后，Final Score 超过多个前沿大模型与专用参考系统（45.32%）。这是 Retained gain 最直观的展示。
- **GUI 的 51 → 79 → 99**：策略与世界模型连续更新两轮，第一轮接受的组合参与第二轮。但注意论文自己的警告：**动作数必须与成功率、错误提交联读**——中间版本动作最少（2.93）却错误提交 21 次，单看动作数会误判。
- **化学 100/100**：100 次运行全部在第 10 次观测内找到候选池最优，平均首次命中 9.94——同预算压过贝叶斯优化 13.99pp。

## 增长曲线怎么读：三条诚实边界

这一节比结果更重要，因为**RSI 数字天然容易被高估**：

1. **单轨迹 ≠ 趋势**。实验室规划的五版本爬升是**一条轨迹上的描述性结果**，没有多种子重复——它证明「发生了」，不证明「通常会发生」。
2. **区间下限很薄，且有硬件敏感性**。代码修复 +2.83pp 的 95% 区间下限只有 +0.17pp；社区 issue #5（截至 2026-10 仍 OPEN）稳定复现了 `recorded` 评测模式在消费级 GPU 上的停机——最可能原因是 bf16 推理在不同 SM 架构上 cuBLAS kernel 选择不同，翻转了边缘分数比较。**引用该增益时应带上「A800 级 GPU」条件**；消费级硬件应改用 `--inputs fresh` 真实重算。
3. **所有数字仍是原始方自证**。第三方核验请求（issue #1，Papers with Code）尚无结论；独立评论与社区质询共同指向同一句话——**「RSI 主张 > 实证闭环」是多个独立观察者的共识**。论文 Discussion 的自陈是诚实的，宣传口径则偏松；引用以论文为准。

## 无人过 L2：RSI 阶梯上的真实位置

把 RSI 分成阶梯：**L0 委派 / L1 净正 / L2 点火 / L3 拐点**，L2 要求「改进者本身被改进」有受控证据。当前状态：

- **L1**：AIDE² 是唯一自称净正的公开系统——8 天 7 版本、reward hacking 55%→32%，但其点火测试三种子不显著，作者自评「不接近智能爆炸」；
- **L2**：**证据为零**。同日 arXiv 检索的 20 篇更新 RSI 论文（2610.14224–2610.20474）全批标题+摘要点检，无一出现 ignition / Level 2 / net positive 主张；
- **验收工具已就位**：PAST-Bench 用 persistence-on/off 配对消融把 Retained gain 变成可证伪测量（七基座 +0.13–+0.24）——缺的不是度量手段，是 L2 证据本身。

RSI-Anything 的位置：**Retained gain 层实证最扎实的系统之一**，配对检查机制为未来的 Improver gain 提供了把关设施——但六步闭环目前没有任何一个域完成策略与世界模型的持续互促（论文自陈的关键缺口）。

## 什么时候值得用

- **反馈预算紧张时**：预测选择的收益以「同测试预算」度量，反馈越贵越划算（实验室、化学、真实用户交互）；
- **有天然验证器的域**：代码修复、GUI 有明确成功判定；化学有实测产率——反馈链短；
- **需要版本管理的长跑系统**：组件 + 配对双检查对任何「两个模型互相当裁判」的架构都可移植，不限于 RSI；
- **不适合**：无外部反馈源的纯内省场景——「LLMs Cannot Self-Correct」负结果仍是下界，闭环的 Evaluate 环不能省。

三大失败模式在选型时就要预埋对策：评测器漂移 / 背题 → 固定外部评测 + 不相交任务 + 独立审计集；奖励与蒸馏坍缩 → 交替训练 + 留出奖励监控；无反馈自纠劣化 → 不要省 Evaluate。

## 复现清单

1. **读框架**：论文 §2 + 仓库 `docs/workflow.md`，搞懂固定/可变边界与 $t/k$ 双时间尺度。
2. **跑最小域**：`rsi plan --config configs/code_repair/evaluate.json` 走评估-only 路径（CPU 可跑的还有反应优化的 321 候选条件目录 + 冻结预测表）。
3. **收一条爬升曲线**：实验室规划跑自己的 5 个保留版本，画 Figure 3 同款——**记得多种子**，别只交单轨迹。
4. **验证配对检查**：人为让一个组件单独变好，确认配对检查能拦下组装后退化——这是机制是否真的必要的消融。

## 总结

RSI-Anything 的贡献排序很清晰：**预测引导选择**省外部反馈（同预算 +2.83pp）、**条件性适应**解决策略进化后预测失效（版本隔离 + 三重触发）、**配对检查**回答「单组件变好 ≠ 组装系统变好」（独门）。五领域实测把它推到 Retained gain 层的最前列，而论文对 L2 级递归性的自陈、社区 issue 的质询与硬件敏感性的复现警示，共同划出了诚实的边界。

**递归自我改进的难点从来不是「变好一次」，而是「变好之后不许变坏」——保留，才是递归的起点。**
